# exec VM census 单用例内存覆盖表
#
# 格式：`用例文件名<TAB>MB`（# 起注释）。没登记的用例用全局
# `UYA_EXEC_CENSUS_MEM_MB`（默认 4096）。
#
# 为什么需要这张表：census 用 `ulimit -v` 限的是**虚拟地址空间**，而 VM 的值
# 竞技场是分段 bump 分配（`src/exec/value.uya`：每段 200MB、
# `EXEC_VALUE_ARENA_MAX_SEGMENTS = 256`）。一个用例跑得越久，开出的段越多，
# 地址空间峰值就越高 —— 这是**分配器形态**，不是泄漏，也不是算错。
# 用全局 4096 去卡会让这类用例在跑到一半时 `[ARENA] grow FAIL`，
# 随后被 `ADDR_INDEX 越界` 这类下游错误伪装成「值模型不对」，排查方向完全错。
#
# 纪律：这张表**只放宽**、不放宽到离谱，且必须写明实测峰值来源。
# 绝不能拿它去掩盖真的内存爆炸或真的语义错误 —— 判定标准是
# 「C99 侧同用例通过 + VM 侧放宽后全通过 + 峰值随轮次数线性增长可解释」。

# test_http_uyagin：27 个用例，VM 侧地址空间峰值 6096MB（第 651 轮实测）。
# 4096 下必然失败，6144 下 27/27 全通过。C99 侧同一用例 1/1 通过。
test_http_uyagin.uya	6144
