# exec VM census 单用例超时覆盖表
#
# 格式：`用例文件名<TAB>秒数`（# 起注释）。两个方向都支持：
#
#   * 放宽 —— 「语义已经对齐、但解释器纯 CPU 开销大」的用例。这类必须给足时间，
#     否则会被误判成失败。
#   * 收窄 —— 「VM 里根本推不动、只会干等」的用例。它们不该被跳过（那会把
#     覆盖率数字做漂亮），但每个都吃满默认超时会把整轮普查拖死，所以给一个
#     短超时让它快速失败。判定结论不变，只是不再白等。
#
# 判别依据：跑的时候看 CPU。CPU 打满 = 纯算得慢（放宽）；CPU 接近 0 =
# 阻塞在 I/O 或死等（收窄）。实测 deterrence 见 docs/todo_exec_vm_parity.md 第 381 轮。

# ---- 纯 CPU 慢（放宽）----
# test_crypto_bigint_modexp4096：4096 位私钥指数模幂 = 6144 次 64×64 Montgomery
# 乘法，解释器实测约 343s（C99 侧约 1s）。内存稳定在 40MB 级别。
test_crypto_bigint_modexp4096.uya	900
# test_crypto_bigint / test_crypto_ed25519：同类纯 Uya 大数运算，解释器比 C99
# 慢两个数量级，默认 120s 会被误判成失败（内容已对齐）。
test_crypto_bigint.uya	300
# test_tls_x25519_pure：纯 Uya 大数实现的 X25519，解释器实测 **665s**
# （C99 侧秒级），内容 1/1 全通过。默认 300s 会把它误判成失败。
test_tls_x25519_pure.uya	900
test_crypto_ed25519.uya	300

# 「确实推不动」，再长只是白烧墙钟时间。
test_async_multi_fd_concurrent.uya	60
