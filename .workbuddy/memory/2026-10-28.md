## exec VM 子系统分析（只读调研 + 实测）

范围：`src/exec/`（10 文件、15,482 行）+ `docs/bytecode_exec_design.md` /
`docs/exec_vm_c99_parity.md` / `docs/todo_exec_vm_parity.md`。

结构结论：
- 分层 `checked AST -> HIR -> bytecode(68 opcode) -> VM`；新增 `format.uya`（printf 家族）。
- `lower.uya` 6406 行 / `builder.uya` 3963 行 / `vm.uya` 2641 行 / `value.uya` 970 行。
- 值模型 `ExecValue` = 56B tagged struct（kind/i64/ptr + aux 三元组复用为 err-union payload
  与引用编码）；聚合/union/slice 全部 `malloc` 装箱、进程内不 free（只有 format.uya 释放）。
- 地址模型两套：真宿主地址（raw array/byte 缓冲）+ "internal ref"（aux_i64 打
  `EXEC_VM_REF_KIND_BASE=65536` / `INDEX_BASE=131072` 标签，指针指向宿主 ExecValue 槽）。
  这是 T13 双指针卡死的根因（kind 与 ref 编码挤在同一字段）。
- 调用模型：`exec_vm_call_function` 递归调用宿主栈；`ExecFrame` 内联 8192 槽
  ×56B ≈ 450KB；每次调用先把 `slots: {0}` 整体清零再循环 8192 次赋 void。
- defer/errdefer 在 builder 期按 cleanup 列表内联展开，无运行时 defer 栈。

实测（用 `bin/uya`，注意该二进制 10-25 04:16 生成、早于 src 10-25 19:56，缺 `exec_format_*`）：
- 300k 次循环：VM 全流程 0.156s vs C99 0.288s（编译占大头），指令分派本身可接受。
- 空函数 20k 次调用 5.88s ⇒ **≈0.29ms/次调用**；fib(24)（≈15 万次调用）45.8s，
  C99 全流程 0.29s。
- 递归深度：默认 8MB 栈下 128 层 OK、160 层 SIGSEGV（无诊断）；栈放到 256MB 时
  1000 层才通过。census/parity 脚本里 `ulimit -s unlimited` 掩盖了这条限制。
- 抽样 50 个 `tests/test_*.uya`：`--vm` 仅 11 通过，37 例 `extern_abi`（消息
  `printf/1`），全部死于 std.testing 的 printf 路径 —— 这是旧二进制的 P1.3 之前状态，
  需先 `make uya` 再复测。

待跟进：重建 `bin/uya` 后复测 census；若要修性能，优先把 frame 初始化/清零从
`EXEC_MAX_FRAME_SLOTS` 改为 `function.slot_count`，并把递归解释器改成显式帧栈。
